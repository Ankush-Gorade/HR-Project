1. Problem Statement & Business Context

Large organisations receive hundreds of job applications per open position. Manual screening is time-consuming, inconsistent, and prone to unconscious bias. A typical recruiter spends 6–8 seconds scanning a resume before making an initial decision, leading to high-quality candidates being overlooked and poor-fit candidates advancing to interviews.

Business Problem: Automate the end-to-end candidate screening workflow — from raw resume submission to a structured hire/reject recommendation — in a way that is fast, consistent, explainable, and auditable.

Inputs

  • Candidate resume (plain text or PDF-extracted)
  • Job description with required/preferred skills
  • Job title and department metadata

Outputs

  • Overall score (0–100) with weighted breakdown
  • Recommendation: Strong Hire / Hire / Hold / Reject
  • Top strengths and concerns
  • Suggested interview topics
  • Next action for the recruiter

3. Sub-Agent Descriptions

Agent 1 — Input Guard Guardrail Agent

File: agents/input_guard_agent.py  |  Tools: None

Role: First line of defence. Validates all inputs before any LLM call is made, preventing wasted compute and prompt injection attacks.

Prompt Strategy: Few-shot with 3 examples covering valid input, gibberish input, and injection attempts. System prompt instructs LLM to return structured JSON confidence scores.

  • Rule-based checks: required fields, length bounds, injection pattern matching
  • LLM-based checks: semantic relevance (is this actually a resume?)
  • Routes to reject node on failure — no further processing
Agent 2 — Resume Parser Extraction Agent

File: agents/resume_parser_agent.py  |  Tools: File processing (PDF/DOCX)

Role: Transforms unstructured resume text into a clean, structured JSON object used by downstream agents.

Prompt Strategy: Chain-of-thought with explicit reasoning steps (identify personal info → scan skills → extract experience → compute totals). Two few-shot examples with diverse resume formats.

  • Extracts: name, email, phone, skills, experience, education, certifications
  • Computes: total_experience_years from individual role durations
  • Keyword-based fallback parser if LLM fails
Agent 3 — JD Matcher Scoring Agent

File: agents/jd_matcher_agent.py  |  Tools: Tavily Web Search

Role: Scores the candidate's technical fit against the job description. Runs in parallel with Agent 4.

Prompt Strategy: Structured reasoning steps: extract JD requirements → compare skills → score each dimension. Two few-shot examples showing strong and partial matches.

  • Scores: skill match (40%), experience match (30%), education match (10%)
  • Uses Tavily web search to fetch current market skill demand context
  • Identifies matched skills and missing required skills
Agent 4 — Behavioral Scorer Analysis Agent

File: agents/behavioral_scorer_agent.py  |  Tools: None

Role: Evaluates soft skills, culture fit, and behavioral signals from resume content. Runs in parallel with Agent 3.

Prompt Strategy: Rubric-based with explicit scoring criteria for each dimension (communication, leadership, teamwork, problem solving, culture fit). Two few-shot examples showing strong and weak behavioral profiles.

  • Detects red flags: job hopping, vague descriptions, gaps
  • Identifies positive signals: quantified impact, leadership, mentoring
  • Contributes 20% to overall weighted score
Agent 5 — Output Guard Guardrail Agent

File: agents/output_guard_agent.py  |  Tools: Gmail MCP, Google Calendar MCP

Role: Aggregates all scores, generates the final report, enforces output quality, and triggers downstream actions.

Prompt Strategy: Report synthesis with explicit scoring weights and recommendation thresholds. Two few-shot examples for Strong Hire and Hold outcomes.

  • Computes weighted overall score: skill(40%) + exp(30%) + behavioral(20%) + edu(10%)
  • Redacts PII from output report
  • Detects biased language in generated text
  • Validates output schema completeness
  • Sends interview invite via Gmail MCP and schedules via Google Calendar MCP

4. Guardrail Strategy

Input Guardrails (Agent 1)

GuardrailTypeWhat it catchesAction
Required field checkRule-basedMissing resume_text, job_description, job_titleReject with error list
Length validationRule-basedResume <100 or >15,000 chars; JD <50 charsReject with reason
Prompt injection scanRule-based"ignore previous instructions", "act as", etc.Reject immediately
Semantic validationLLM-basedGibberish, non-resume content, fake credentialsReject with LLM reasoning

Output Guardrails (Agent 5)

GuardrailTypeWhat it catchesAction
PII redactionRegexEmail, phone, SSN in output reportReplace with [REDACTED]
Schema validationRule-basedMissing required report fieldsLog warning, fill defaults
Score bounds checkRule-basedScores outside [0, 100]Clamp and log warning
Bias detectionRegexAge, gender, religion, nationality referencesFlag in report metadata
Why two layers? Input guardrails protect the system from malicious or malformed data before expensive LLM calls are made. Output guardrails protect end-users and the organisation from harmful, biased, or non-compliant report content.

5. Orchestration Pattern

PatternWhere UsedJustification
Conditional Routing After Agent 1 (Input Guard) Invalid inputs must be terminated early to avoid wasting LLM calls on malicious or malformed data. The route_after_input_guard() function directs flow to either resume_parser or reject based on input_valid flag.
Parallel Fan-out/Fan-in Agents 3 & 4 run concurrently JD matching (technical fit) and behavioral scoring (soft skills) are independent tasks with no data dependency. Running them in parallel reduces total pipeline latency by ~50% versus sequential execution.
Human-in-the-Loop After parallel scoring HR screening decisions affect people's careers. A human checkpoint before the final report ensures a recruiter can review intermediate scores, catch LLM errors, and request refinement in high-stakes cases.
Iterative Refinement Loop Human review → re-score When a reviewer disagrees with scores, the pipeline re-runs Agents 3 & 4 rather than starting over. A safety cap of 3 iterations prevents infinite loops.

8. Prompt Engineering

All prompts are stored as Markdown files in the prompts/ directory and loaded at runtime via utils/helpers.load_prompt(). This keeps prompts version-controlled and editable without code changes.

Techniques Used

TechniqueApplied InPurpose
Few-shot examplesAll 5 agentsGround the LLM with 2–3 concrete input/output examples reducing hallucination
Chain-of-thought / reasoning stepsResume Parser, JD MatcherExplicit numbered steps force systematic extraction before producing output
Role assignmentAll agents"You are an expert HR resume parser" sets the persona and domain context
Output format specificationAll agentsExplicit JSON schema in prompt ensures parseable, structured output
Rubric-based scoringBehavioral ScorerHigh/Medium/Low criteria for each dimension reduce subjective variance
Constraint injectionOutput GuardExplicit scoring weights and thresholds prevent LLM from inventing its own rules

Example — Reasoning Steps in Resume Parser Prompt

## Reasoning Steps 1. First identify the candidate's personal information (name, email, phone) 2. Then scan for all technical and soft skills mentioned 3. Extract each work experience entry with dates and calculate duration 4. Sum all experience durations for total_experience_years 5. Extract education entries 6. Format everything into the required JSON structure

Metric Choice Rationale

Field-level Precision/Recall/F1 was chosen over simpler accuracy metrics because it separately measures the agent's ability to correctly identify each extracted field. This is appropriate for an extraction task where partial correctness matters — a parser that correctly extracts skills but misses experience years is worse than one that gets both right.

Failure Analysis

No failures were detected across all 20 test cases. The LLM-based parser with chain-of-thought reasoning steps successfully handled all resume formats including: fresh graduates with no experience, senior engineers with 10+ years, non-technical roles (HR, Finance, PM), and resumes with missing fields like email or phone.

Known Limitations

  • Test cases used plain text resumes — PDF formatting artifacts may reduce accuracy on real uploads
  • Non-English resumes were not tested and may perform worse
  • Very unusual date formats (e.g. "since 2019") may cause experience year calculation errors
  • The evaluation metric is field-level binary (correct/incorrect) rather than semantic similarity scoring

11. Reflections, Limitations & Improvements

What Worked Well

  • LangGraph StateGraph made pipeline orchestration clean and explicit — every edge and routing decision is visible in code
  • Fallback parsers in every agent ensured the pipeline never crashed even when LLM calls failed
  • Prompt markdown files kept prompts editable and version-controlled separately from code
  • Modular structure made each agent independently testable
  • Groq's free tier provided fast, cost-effective LLM inference for development and testing

Limitations

  • No true parallelism — Agents 3 & 4 run sequentially in the current implementation due to Colab's synchronous execution; production would use LangGraph's Send API for true concurrency
  • Groq rate limits — Free tier has rate limits that slow down batch evaluation runs
  • MCP tools — Gmail and Calendar MCP integrations log intent but require OAuth setup for full functionality
  • No persistent state — Pipeline state is in-memory only; a production system would use a database for resume storage and retrieval
  • English-only — Prompts and guardrails are optimised for English resumes only

Potential Improvements

  • Add a Skills Gap Recommender agent that suggests learning resources for missing skills
  • Integrate LinkedIn profile scraping to verify work history claims
  • Add multi-candidate ranking to compare a pool of candidates for the same role
  • Implement true parallel execution using LangGraph's Send API with async agent nodes
  • Add a feedback loop where recruiter decisions improve the scoring model over time
  • Build a React dashboard for recruiters to view, approve, and manage pipeline results
